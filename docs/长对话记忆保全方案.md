# 长对话记忆保全方案

本仓库采用七层保护,分别处理静默工具、手机断线、单轮卡死、进程死亡、窗口压缩、
未完成事件尾巴和平台滚动重启。

## 一、连接还活着但工具暂时无输出:SSE 心跳

`sse.js` 在收到 Kelivo 请求后立即刷新 HTTP 响应头,并在 WebSearch、WebFetch 或 MCP
静默执行期间每 15 秒发送标准 SSE comment。comment 不进入对话内容,只防止 Kelivo、
Zeabur 或中间代理把“暂时没有文字”误判成死连接。

## 二、手机连接断了:同轮重连与短期回信箱

Claude 轮次不随手机 SSE 断开而取消。相同请求在仍执行时重新接入,`delivery.js` 会把
新连接附着到原轮,先重放已生成文字,随后继续接收;不会再向 Claude 发送一次。

最近五个成功回复在 `/persona/turn-state/mailbox.json` 保留 3 分钟。即使 Claude 已完成、
Kelivo 没收到,重发同一句也直接取回原回复。请求指纹包含模型、世界书和聊天历史;
连续的相同用户重发会折叠,但有新的 assistant 回复介入后就视为新一轮。

## 三、当前轮卡住:先中止本轮

五分钟没有收到任何 Claude stream-json 事件时,shim 先发送 Claude Code 原生
`control_request/interrupt`,只取消当前轮,不杀常驻进程。宽限 60 秒仍没有 result,
才硬重启进程。对论坛发帖、邮件等有副作用的工具,前端会提醒先确认动作是否已经完成,
避免盲目重发造成重复操作。

中止或进程退出后不会自动重发原用户消息,包括 WebSearch、WebFetch 等只读任务。当前轮
可以放弃,由用户看到本地提示后自行决定是否重新询问;后台只保护原生 session 的存续。

## 四、常驻进程还活着:压缩保护

1. `window.js` 从每次 API 请求自己的 `message_start.usage` 计算真实前缀。
   不使用 `result.usage`,因为一轮多次工具调用时它是累加值,会虚报数倍。
2. 当前默认模型是 1M 上下文,Claude Code 的 auto-compact 窗口固定为 1M,shim 的
   监测线与之同源:约 967k 触发压缩,80% 提醒,85% 排队执行一次 OB `grow`。
3. 自动归档读取 `grow` 的真实返回,只有新建数+合并数至少为 1 才算完成;
   失败会解除去重锁,在后续轮次重试。旧 `archive_session` 仅保留兼容。
4. `PreCompact` 默认使用安全摘要:仍保留近期上下文作为兜底,并要求压缩后第一轮
   `breath(wake=true)`。`COMPACT_SUMMARY_MODE=slim` 才会启用一行摘要,不建议默认开启。

## 五、进程已经死了:原生 session 优先

`entrypoint.sh` 把 Claude Code 的 `~/.claude/projects` transcript 目录接到持久卷
`/persona/claude-state/projects`;`session-state.js` 同时保存 session ID。模型和系统提示词
指纹一致时,进程重启使用 `claude --resume <session-id>`,因此恢复的是 Claude Code 自己的
原会话,包含它真正经历过的消息与工具过程,不是把最近对话伪装成一份摘要。

聊天文字永远不会触发新 session;即使说到“换窗口”,shim 也只把它当作普通对话。主动
切模型或改变世界书才会从聊天外创建新 session,不会要求对方参与告别操作。
如果原生 transcript 缺失会先恢复滚动副本。若 resume 被 CLI 明确拒绝,shim 会先原样
重试一次;仍被拒绝才保留那份可能更新但异常的原文件,自动换入最近一份通过大小和 SHA-256
校验的副本,并用**同一个 session ID**再试一次。只有这条同 session 抢救路径仍失败,才
进入下面的 Kelivo 历史兜底。网络、鉴权或启动故障不算 session 损坏,只会带退避地继续
重试原会话,不会因此降级。整个过程自动完成,不需要使用者确认。

每轮结束后还会为当前原生 transcript 更新最近一份滚动副本。原文件缺失时自动恢复
最新副本;只有 Claude Code 已明确拒绝 resume 时才旁存异常原件、换入已校验副本,不会
删除可能包含更新经历的现场。

### Kelivo 历史兜底

Kelivo 每次请求会带当前聊天的若干条历史。`history.js` 只在新 Claude 进程收到的
第一条 Kelivo 消息中,把这些旧消息作为“会话恢复材料”与当前消息一起送入。之后继续
依靠常驻进程,不会每轮重复历史。

因此普通聊天、意外重启会续接原窗口;主动切换模型或世界书则是真正的新 session。

兜底默认接收 Kelivo 在请求中实际提供的全部历史,不再先人为截成最近 128 条;字符预算
默认跟随 Claude Code 窗口的 60%,为系统提示、工具定义和新回复留出空间。可用下列变量调整:

| 变量 | 默认 | 用途 |
|---|---:|---|
| `REHYDRATE_MAX_MESSAGES` | 不限条数 | 可选:人为限制重启时恢复多少条历史 |
| `REHYDRATE_MAX_CHARS` | Claude Code 窗口的 60% | 可选:重启恢复文本字符上限 |
| `SESSION_RESUME` | `1` | 设为 `0` 关闭 Claude Code 原生 session 续接 |
| `SESSION_STATE_FILE` | `/persona/claude-state/shim-session.json` | 原生 session 指针文件 |
| `SSE_HEARTBEAT_MS` | `15000` | 静默期 SSE 心跳间隔;设 `0` 关闭 |
| `TURN_TIMEOUT_MS` | `300000` | 多久无 Claude 事件后尝试中止本轮;设 `0` 关闭 |
| `TURN_INTERRUPT_GRACE_MS` | `60000` | 温和中止后等待多久才硬重启 |
| `TURN_STATE_DIR` | `/persona/turn-state` | 当前轮事件日志与短期回信箱 |
| `MAILBOX_TTL_MS` | `180000` | 已完成回复可按原请求取回的时间 |
| `WAKE_CHECK_MIN` | `10` | 自主唤醒本地检查频率;检查本身不调用 Claude |
| `WAKE_IDLE_MIN` | `50` | 新加坡时间 08:00-24:00 内的空闲阈值;实际约 50-60 分钟触发 |
| `SESSION_BACKUPS` | `1` | 每个原生 session 保留多少份 transcript 滚动副本 |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | `1000000` | Claude Code 自动压缩窗口;换成小窗口模型时要同步调整 |
| `WINDOW_WARN_PCT` | `80` | 通知使用者的百分比 |
| `WINDOW_ARCHIVE_PCT` | `85` | 自动归档百分比 |
| `WINDOW_AUTO_ARCHIVE` | `1` | 设为 `0` 关闭自动归档 |
| `COMPACT_HOOK` | `1` | 设为 `0` 关闭 PreCompact 钩子 |
| `COMPACT_SUMMARY_MODE` | `safe` | `safe` 保留兜底;`slim` 一行摘要 |

## 六、当前轮的本地事件日志

`turn-state.js` 在持久卷记录当前轮的输入、工具开始、参数、返回状态、已输出文字与
结束原因。它不保存隐藏 thinking,也永远不会把这些内容作为提示词交给 Claude;记录只供
本地排错与回信箱判断。当前轮失败后由用户决定是否重新询问。

## 七、平台重启规则

SIGTERM 到来后,shim 先停止接收新轮、保存事件日志并温和 interrupt 当前轮,等待最多
20 秒后才退出。这样 Zeabur 的滚动更新不再等同于突然拔电。

原生 session 大幅降低意外重启造成的断层,但它仍不是异地备份。计划部署或主动切模型前
仍应先归档并确认成功;Kelivo 全部可用历史只在同 session 原文件与校验副本都失败时兜底。
